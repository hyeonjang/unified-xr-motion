MotionDAG is guided by three design principles: modular composition, interface-driven extensibility, and device-agnostic execution.
Creators can build pipelines tailored to their XR devices—cloning presets, swapping tracking inputs, reordering motion processing stages, or mixing local and remote nodes—without writing code, while still benefiting from guaranteed data-flow compatibility. 

Motion pipelines are expressed as DAGs in which each component conforms to a common \textbf{Motion Node} interface. This interface defines standardized input and output contracts, enabling nodes to be composed, reordered, or substituted while preserving graph semantics.
Extensibility is achieved through interface-driven abstraction: developers introduce new functionality by implementing interface-compliant nodes, and existing pipelines remain valid as long as contract requirements are satisfied. The interface further distinguishes between \textbf{Motion Sender} and \textbf{Motion Receiver} roles, which formalize data publication and subscription within the graph.
